# 中文工作文档书写规范

本规范用于正式工作文档、Markdown、汇报、方案、周报、复盘、说明材料和格式审校。它补充标题、段落、中英数混排、标点、数值和来源标注，不替代沟通策略与句法判断。

## 使用边界与优先级

格式服务于准确和阅读，不应反过来改变事实、术语或承诺。发生冲突时，按以下顺序处理：

1. 用户明确要求；
2. 组织规范、既有模板或发布平台要求；
3. 法律、行业和技术标准；
4. 产品、品牌和专有名称的官方写法；
5. 本规范的默认建议。

不要为了统一中文格式而改动代码、命令、URL、文件路径、版本号、接口字段、账号、编号或其他机器可识别内容。引文需要忠实呈现时，也不要擅自改写原文。

## 一、标题说明内容，不制造层级

- 标题应帮助读者定位内容。优先写明对象、结论、问题或动作，少用“背景与意义”“相关情况”等不能单独提供信息的标题。
- Markdown 标题按层级连续使用，不从一级标题直接跳到三级标题。
- 某个标题下只有一个子标题时，通常取消这一子层级；下级标题不要重复上级标题的名称。
- 普通工作文档尽量控制在三级标题以内。三级标题下只有少量并列内容时，优先使用列表，不再增加四级标题。
- 标题末尾通常不用句号、逗号、分号或冒号。问号、叹号确实属于标题含义时可以保留，但工作文档应少用感叹号。
- 不要为了版式整齐，强行让每一节拥有相同数量的小标题或要点。

## 二、一个段落承担一个主要任务

- 一段主要说明一个判断、变化、原因、风险或动作。主题、时间、责任人或逻辑关系明显变化时，考虑另起一段。
- 汇报和说明材料通常把结论、变化或问题放在段落前部，再补证据和解释。涉及异议、坏消息或情绪沟通时，可以先交代必要背景和影响，不把“中心句必须在首句”当成硬规则。
- 并列事实、选项或行动项较多时，用列表或表格帮助扫读；连续的因果、推理和说明保留自然段。
- Markdown 段落之间空一行，段首不输入空格模拟缩进。若既有模板要求首行缩进或紧凑排版，遵循模板。
- 避免“一逗到底”。一个句子包含多层完整关系、读者需要回看才能理解时，拆成几句；不按固定字数机械断句。
- 直接引用、转载内容或外部图片应注明来源。

## 三、中英数混排保持一致

- 中文句子使用全角中文标点；完整英文句子使用半角英文标点。
- 在普通 Markdown 和纯文本中，中文与英文单词、缩写或产品名之间通常留一个半角空格，如“使用 Git 管理版本”。官方名称有特殊写法时保留官方形式。
- 中文与半角阿拉伯数字之间是否留空格，按组织或平台习惯决定；同一份文档保持一致。
- 英文、数字与紧随其后的中文标点之间不留空格，如“安装 Python，然后运行脚本。”
- 数字与拉丁字母单位之间通常留一个半角空格，如“16 GB”。百分号、角度符号、货币符号等按相应标准或既有模板处理，不机械套用空格规则。
- 专有名称使用官方大小写，不自行把所有单词改成首字母大写。
- 在 Markdown 中，代码、命令、URL、路径、文件名、版本号和标识符使用代码格式，并保留原有半角字符。

## 四、标点表达真实关系

- 中文并列词通常用顿号分隔；最后两项使用“和”“与”还是继续用顿号，取决于是否更容易读清关系。
- 逗号表示句内停顿，不代替所有句号和分号。两个分句各自完整、关系又较远时，优先断句。
- 引用一般使用全角双引号“”；引号内再次引用时使用单引号‘’。代码和字段名优先使用代码格式，不用中文引号包裹。
- 中文补充说明一般使用全角圆括号（）。括号内是完整英文、代码或公式时，可按原内容使用半角括号。
- 中文省略号在同一文档中统一使用“……”或“⋯⋯”，不要写成“...”或“。。。”，也不要与“等”重复表达省略。
- 感叹号和问号不要重复连用。平静陈述能够表达清楚时，不靠标点制造语气。
- 数值范围在正文中优先写“至”，如“10% 至 15%”；表格或密集数据中可以使用统一的连接号。不要同时混用多种范围符号。
- 句末括号是对句内内容的补充时，句号通常放在右括号之后；括号本身构成独立句子时，按独立句处理。

## 五、数字、单位和变化写清基准

- 阿拉伯数字使用半角形式。用于计量、统计、金额、日期、时间、百分比和编号时，通常比汉字数字更容易识别；成语、惯用语和概数可按自然中文写法处理。
- 报告变化时，尽量同时给出基期、结果和变化量，如“从 100 增至 120，增加 20%”。不要只写“大幅提升”。
- 区分“增加到”和“增加了”：从 1 变成 2 是“增加到两倍”或“增加了 1 倍”；“增加了两倍”通常表示从 1 变成 3。容易误读时直接写原值和现值。
- 不写“降低 N 倍”或“减少 N 倍”。改写成“降至原来的几分之几”“减少百分之几”，或直接给出前后数值。
- 百分比与百分点不是一回事。例如从 20% 升至 25%，可以写“提高 5 个百分点”或“增长 25%”，不能混用。
- 范围两端共用同一单位且不会误解时，单位可以只写一次；需要单独引用、对齐比较或避免歧义时，两端都写单位。
- 较长数量可以使用千分位提高可读性，但年份、页码、版本号、证件号、订单号、电话号码等编号不得因此插入分隔符。
- 金额使用货币符号或货币名称即可，避免同一数值重复标记币种。跨币种材料应明确币种，不能只写“元”。
- 同一张表中的单位、币种、小数位和日期格式应保持一致；确有差异时在表头或注释中说明。

## 六、引用和来源要让读者能够复核

- 外部数据、直接引语、图片和影响关键判断的事实，应在相邻位置注明来源，不把所有链接堆到文末后让读者猜对应关系。
- 来源标注至少提供能够定位原文的信息，如机构或作者、文档标题、发布日期或版本、直接链接。内部材料按权限允许的方式给出文件名、版本或文档位置。
- 转述使用自己的语言，并确保没有改变原意；逐字引用使用引号或引用块。不要把转述伪装成原话，也不要编造页码、发布日期或链接。
- 二手来源无法支撑关键结论时，查找原始文件、标准、数据集或官方说明。只能使用二手来源时，明确说明来源层级。
- 简短工作消息不必附完整参考文献表。一个能直接打开、准确对应当前事实的链接，通常比笼统写“据公开资料”更有用。

## 快速审校清单

- [ ] 标题是否连续分级，且每一级都有存在价值？
- [ ] 每段是否主要承担一个判断、解释或动作？
- [ ] 结论、变化或问题是否出现在读者容易找到的位置？
- [ ] 中英文、数字、单位和标点的间距是否统一？
- [ ] 代码、URL、路径、版本号和编号是否保持原样？
- [ ] 是否存在“一逗到底”、混用括号引号或重复感叹号？
- [ ] 数值变化是否写清基准、结果和单位？
- [ ] “增加了／增加到”“百分比／百分点”是否准确？
- [ ] 千分位是否误加到了年份、版本号或其他编号中？
- [ ] 外部数据、引语和图片是否能够回到原始来源复核？
- [ ] 格式调整是否改变了原意、事实、术语或承诺强度？

## 来源与取舍

本规范不是原文摘录，而是面向中文工作文档的筛选、改写和补充。

- 《[文本](https://github.com/ruanyf/document-style-guide/blob/master/docs/text.md)》：中英数混排、长句、肯定表达、指代和英文处理。
- 《[段落](https://github.com/ruanyf/document-style-guide/blob/master/docs/paragraph.md)》：一段一意、段落间距以及引文和图片来源。
- 《[数值](https://github.com/ruanyf/document-style-guide/blob/master/docs/number.md)》：半角数字、货币、范围以及“增加了／增加到”“降低了／降低到”的区别。
- 《[标点符号](https://github.com/ruanyf/document-style-guide/blob/master/docs/marks.md)》：全角与半角标点、顿号、引号、括号、省略号和感叹号。

### 校验与补充

- 教育部发布的 [GB/T 15834—2011《标点符号用法》](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091548267.pdf)：用于校验中文标点的一般用法和括号内外标点。
- 教育部发布的 [GB/T 15835—2011《出版物上数字用法》](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091154536.pdf)：用于校验数字形式、计量、编号、范围和单位表达。
- W3C《[中文排版需求](https://www.w3.org/TR/clreq/)》：用于补充数字环境中的中文标点字形、Unicode 表示、断行和中西文混排问题。

### 本规范的主要调整

- 不采用“句子超过 40 字一律不可接受”“段落不超过七行”等硬性长度限制，改为按信息负担和可读性判断。
- 不要求所有段落的中心句必须位于首句；正式报告优先结论前置，敏感沟通保留必要铺垫。
- 不采用“英文复数一律还原为单数”“英文词首次出现一律加中文标注”等绝对规则，改为按语义、读者和术语熟悉度判断。
- 不纳入软件手册目录和文件命名规则，因为它们不属于通用中文工作沟通规范。
- 不固定唯一的省略号、连接号等 Unicode 字符；具体形式服从标准、组织规范和发布平台，并要求同一文档保持一致。
