# ai-detox — 检测并重写 AI 味 / 中式黑话文本

检测中文文档中的 AI 生成痕迹、企业黑话、空洞套话，输出八类命中计数 + 逐条标注 + 双语气改写。

触发词：检测到 ai-detox、de-aiify（旧名别名）、去AI味、黑话检测、文本去AI化等请求时激活此技能。

## Quick Reference

贴文档链接或粘贴文本，Claude 默认全量输出（扫描报告 + 改写）。追加关键词跳过步骤：

| 关键词 | 效果 |
|--------|------|
| `[仅检测]` | 只出扫描报告和命中标注，不给改写 |
| `[单句]` | 只分析一句话，跳过全文扫描 |

扩展口：自定义词表见 `references/blacklist.md`，用户可追加条目无需改本文件。

## 异常处理（固定动作）

| 异常 | Claude 必须做的事 |
|------|------------------|
| 飞书 403 权限错误 | 告知"权限不够，请检查登录状态"，要求提供纯文本 |
| 文档 > 2万字符 | 先读 outline 让用户选章节再读，避免截断 |
| 全文 > 8000字 | 按段落分块扫描，逐块报告，最后汇总 |
| detect.py 不可用 | 完全走 Claude 规则扫描，功能一致只是少了 CLI 出口 |

## 输入处理

1. 含 feishu.cn/docx/ 链接或 doc token → 用 feishu MCP `doc_read` 读取全文
2. 否则直接使用用户提供文本
3. 进入检测流程

## 铁律

**宁可漏检，不可误报。** 误杀一个干净文档比漏掉一句 AI 味更严重。

只收"空泛借喻词"——替换为日常用语后语义不变但人味儿增加。正常业务术语放行（迭代、优化、兼容、量化、支撑、协调）。

有实指放行：词后紧跟具体系统名/数字/技术动作/专名（如"GAID映射打通""沉淀用户行为标签"），此时放行；后跟普通名词宾语不构成实指，照常命中。

## 检测规则速查（八大类）

完整定义见 `references/blacklist.md`。以下是最简对照表：

| # | 类别 | 颜色 | 特征 | 典型信号 |
|---|------|------|------|---------|
| 1 | 借喻式黑洞词 | 🔴 | 军事/体育/农业隐喻被掏空 | 赋能、抓手、打通、沉淀、闭环… |
| 2 | 元话语 | 🟠 | 说自己在说但不说事 | 我们可以看到、值得注意的是、需要强调 |
| 3 | 万能修辞模板 | 🟡 | 放哪篇都行拿掉不影响实质 | 在当今XX下、随着XX发展、各方共同努力 |
| 4a | 排比癖 | 🟢(4a) | ≥3个三连并列 | 实现了A、提升了B、增强了C |
| 4b | 虚化程度 | 🟢(4b) | 副词+抽象结果无数字 | 大幅/显著/有效+提升/优化/改善 |
| 4c | 后缀病 | 🟢(4c) | ≥2后缀词同句 | -化/-性/-型/-度（系统化/可扩展性/颗粒度） |
| 4d | 万能程度副词 | 🟢(4d) | 把断言弱化为不为空 | 一定程度上/某种程度上/或多或少 |
| 4e | 欧化句型 | 🟢(4e) | 英文骨架硬套中文 | 不是X而是Y/是……的判断句壳/"进行"+名词 |
| M | 修饰膨胀 | 🟢(M) | ≥2类空泛修饰堆叠+无数字 | 全球范围×广泛×积极×持续向上 |
| ⚫ | 标点级 | ⚫ | 机械扫描标点/排版信号 | 破折号>2、半角标点、引号抽象词、满屏加粗(≥4处) |
| 🔵 | 占位语气 | 🔵 | ≥2个占位短语叠用 | 以...为准 + 暂定 + 灵活调整 |
| 🟤 S1 | 背景开篇病 | 🟤 | 以时代/趋势铺垫开篇 | "在XX竞争日益激烈的环境下" |
| 🟤 S2 | 目标空洞病 | 🟤 | 动词+名词并列无量化结果 | "打通…沉淀…形成…" |
| 🟤 S3 | 价值虚化病 | 🟤 | 价值断言无基线数据 | "有效提升效率"没说有提升多少 |
| 🟤 S4 | 空总结段病 | 🟤 | 独立总结段信息量为零 | 全文总结/展望段无事实无行动项 |
| 🟤 S5 | 安全对齐痕迹 | 🟤 | RLHF语气惯性≥2处 | 负责任地/值得深入探讨/应该客观评估 |
| 🟤 S5a | 合规腔嵌套 | 🟤 | 前置条件从句稀释主张 | "在符合XX的前提下"/"遵循XX原则的基础上" |
| 🟤 S5c | 信息密度病 | 🟤 | 段落>50字且事实字符占比<10% | 大段文字几乎全是空泛修饰 |

豁免备注：JSON/code/Markdown链接中的半角标点已排除；前者/后者配对出现一次不触发欧化检测。

## 执行流程（5步固定动作）

```
1. 读入文本    飞书链接→MCP读取 / 纯文本→直接使用
2. 提取事实    扫描全文列出所有数字、专名、系统名、技术动作
3. 八类扫描    依次匹配并记录每处命中的位置/原文/建议操作
4. 判决删除    逐句问"删了丢什么事实？"=0→整句删除；≠0→保留改写
5. 改写交付    每段直白版+专业版+保留事实清单勾稽
```

第八类（🟤行文结构病）输出整段结论，不参与单句级计数，单独汇总。

## 改写交付格式（固定模板）

### 单句模式 `[单句]`

```
原句："{原文}"
命中：🔴 赋能 / 🟢(4b) 虚化程度（有效+提升无数字）
直白版：[改写] — 像跟同事说话
专业版：[改写] — 正式但不端着
建议：删除 / 保留改写
```

### 全文模式（默认）

```
🔍 检出 N 处: T=黑话O=元话语Y=万能修辞B=结构癖M=修饰膨胀P=标点U=占位语气S=行文结构病

═══ 🔴 ═══ [行N] "{原文}" → "{建议}"
═══ 🟠 ═══ [行N] "{原文}" → 删除或替换
═══ 🟡 ═══ [行N] "{原文}" → 建议删除
═══ 🟢 ═══ [行N-M] "{片段}" → "{问题}" (子类计数)
═══ 🟢(M) ═══ [行N-M] "{片段}" → "修饰膨胀(规模,广度)" — {N}类堆叠无数据
═══ ⚫ ═══ [行N] "{原文}" → "{建议}"
═══ 🔵 ═══ [行N-M] "{片段}" → "命中：暂定/灵活调整"
═══ 🟤 ═══ [行N] {诊断结论}
```

#### 逐段改写

```
> **第 N 段（原："[摘要]"）**
> **直白版**：[改写] — 像跟同事说话
> **专业版**：[改写] — 正式但不端着
> **保留事实清单**：
> - [✓] Q3 DAU 从 500 万降至 420 万
> - [✓] RU 搜索无结果率 15.9%
> ✅ 该段所有事实和数字已保留
> **可删段落建议**：[行N-M] 无实质信息，建议删除
```

受保护跨度（改动任意一项 = 改写失败）：数字统计、专名术语、谓词方向（升/降/增/减）、效果类型、关系类型、模态（必须/可以/不得）、硬机制实现、证据引用。只能原样保留或标注「（原文未提供）」留空，不得改写增删。

## 示例

**原文**：在当前数字化转型的背景下，我们需要以用户痛点为抓手，通过技术赋能实现服务闭环，形成一套可复用的方法论。

**计数**：T=3 / Y=1 / S=2(S1+S3)
**直白版**：我们要找出用户最头疼的问题，用技术解决，把流程跑通，留下能复用的做法。
**专业版**：围绕用户核心痛点，应通过技术手段打通全流程，形成标准化、可复用的方法。

---

**原文**：本项目实现了流程优化、提升了协作效率、增强了团队透明度。

**计数**：B=1(4a排比)
**直白版**：这个项目把流程理顺了，大家配合更顺，团队进度也透明了。
**专业版**：项目将流程标准化，减少跨部门沟通成本，并通过共享看板提升进度可见性。

## 注意事项

- 检测基于模式匹配 + 词典，不是主观审美评判
- 计数是客观事实，不编造主观评分
- 改写仅提供两种风格，不做更多变体
- 改写不得新增原文未出现的事实、数字或例子；缺数据用「（原文未提供）」标注
- 合规边界：《人工智能生成合成内容标识办法》要求 AI 生成内容添加标识，本 skill 去 AI 味是文本润色，**不构成对 AI 内容标识义务的豁免**
- 评测集见 `references/gold_tests.md`（正例 ≥9/10，负例误报 0/5，语境负例误报 0/8）
