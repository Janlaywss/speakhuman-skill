# ai-detox 黑话词表 v0（内部参考，不在 SKILL.md 中硬编码）

## 筛选原则（铁律）

**只收"空泛借喻词"**：替换为日常用语后语义不变、但人味儿增加。
正常业务术语**放行**，即使它们偶尔被 AI 滥用——误杀一个干净文档比漏掉一句 AI 味更严重。

区分标准：
- **要洗的牙**：空洞借喻，字面有意义但实际没传达信息 → 赋能、抓手、打通、沉淀…
- **好牙（放行）**：精确的技术/业务术语，换了反而降低准确性 → 迭代、优化、兼容、量化、支撑、协调

## 🔴 第一类：借喻式黑洞词

特征：本意来自具体场景（军事/体育/农业），搬到文档里变成空洞占位符。
替换后语义几乎完全不变，只是读起来不像机器写的。

| 词 | 建议替换 | 理由（为什么像 AI） | 误报风险 |
|----|----------|-------------------|---------|
| 赋能 | 帮助 / 让…能做 | 军事隐喻滥用，本质就是"帮"；仅后跟具体系统名/数字/技术动作/专名时放行（如"GAID映射赋能"），后跟普通名词宾语（"赋能团队"）照常命中 | 低 |
| 抓手 | 具体动作或工具名 | 没有实质含义，读者不知道你到底指什么 | 低 |
| 打通 | 连接 / 合并 / 贯通 | 建筑隐喻替代了具体动词 | 低 |
| 沉淀 | 积累 / 留存 / 形成 | 农业隐喻，换掉不影响理解 | 低 |
| 协同 | 配合 / 合作 | "协同"本身是正常词，加"-ed"后缀（"加强协同"）时必杀 | 中 |
| 矩阵 | 系列 / 组合 | 数学词汇当包装纸用 | 低 |
| 闭环 | 完整流程 / 端到端 | 控制论术语被掏空 | 低 |
| 组合拳 | 多项措施 / 一揽子方案 | 体育隐喻，直接说有几项就行 | 低 |
| 顶层设计 | 整体规划 | 建筑隐喻掩盖了具体的设计内容 | 低 |
| 方法论 | 方法 / 思路 | "方法论"听起来比"方法"高级但没更多信息量 | 低 |
| 生态 | 生态系统 / 相关方网络 | 生物隐喻，80% 情况后面紧跟的才是重点 | 低 |
| 联动 | 互动 / 互相影响 | 和"协同"类似，加了前缀就危险 | 中 |
| 倒逼 | 迫使 / 推动 | 逆向因果隐喻，实际想说的可能是"因为 X 所以 Y" | 低 |
| 聚焦 | 关注 / 集中资源在 | "聚焦"之后必须有具体对象才算有用 | 低 |
| 拉齐 | 统一 / 对齐 / 保持一致 | 口语化版就是"对齐"，书面语也不好在哪 | 低 |
| 驱动 | 推动 / 带动 | 机械隐喻泛滥，90% 可替换 | 低 |
| 贯穿 | 全程 / 从头到尾 | 方向性隐喻，换成时间/空间描述即可 | 低 |
| 落地 | 实施 / 执行 / 上线 | 降落隐喻，技术圈最爱用的一个 | 高* |
| 解法 | 解决方案 / 办法 | "解法"本身不是问题，问题在"提供了解法"这种空洞句式 | 低 |
| 布局 | 规划 / 安排 | 棋类隐喻，通常后面应该跟具体布局了什么 | 低 |
| 壁垒 | 系统障碍 / 信息孤岛 / 跨部门困难 | "打破壁垒"是经典AI套话，换掉后信息量不变 | 低 |
| 破局 | 找到突破口 / 改变现状 | 棋类隐喻替代了具体问题描述 | 低 |
| 痛点 | 具体问题 / 待解决事项 | 医学隐喻被掏空；"从痛点出发/解决用户痛点"空泛 | 高* |
| 打法 | 具体方法 / 步骤 | 体育隐喻；有实指（"打法=具体方法"）时放行 | 中 |
| 负责任地 | 直接给结论 | RLHF 训练痕迹：用"负责任地/伦理地/适当地"替代明确判断，原文是 "responsibly/ethically/appropriately" | 低 |
| 需要谨慎看待 | 给出明确判断或标注"待确认" | Affective Default Lock-In 论文(arXiv 2606.08172)：安全对齐模型回避风险的语气惯性 | 低 |
| 值得深入探讨 | 说清楚值不值得、为什么 | 表演性留余地——RLHF 模型的"不把事情说死"倾向 | 低 |
| 应该客观评估 | 直接做评估或标注"待验证" | 同左，用"客观"包装不判断 | 低 |
| 多方共同努力 | 列出具体谁+做什么 | CCT(文化共识理论)揭示的"无主体万金油"——换哪篇都行 | 极低 |
| 奠定了坚实基础 | 删或用具体成果替代 | 建筑隐喻空洞化，RLHF 常见收尾套路 | 低 |

\* "落地"在"需求已落地/功能已落地"中可接受，仅检测"落地为XX"或"落地方案"等空洞用法。
\* "痛点"做表格分类标签（如"核心业务痛点："后跟具体列举）或有实指时放行，仅空泛用法命中。

## 🟠 第二类：元话语（说了"要说的事"但没说事）

特征：句子本身 grammatically correct，但信息量为零——它告诉你作者在写一段，不告诉你写了什么内容。

| 短语 | 建议操作 | 理由 | 误报风险 |
|------|---------|------|---------|
| 我们可以看到 | 删掉，直接陈述事实 | 没有人关心"我们看到"这个动作 | 极低 |
| 我们发现 | 删掉，直接说发现了什么 | 同上 | 极低 |
| 值得注意的是 | 删掉或用冒号替代 | 经典 AI 铺路词，信息量为零 | 极低 |
| 从某种意义上说 | 删掉 | 万能缓冲词，真正重要的主张不需要缓冲 | 极低 |
| 需要强调的是 | 删掉 | AI 最爱用来假装强调的词 | 极低 |
| 应该说 | 删掉或直接改说法 | 自我修正标记留在正文 = 未处理痕迹 | 低 |
| 不可否认的是 | 删掉 | 废话中的废话——有什么不可否认？ | 极低 |
| 必须承认 | 删掉 | 同左 | 极低 |
| 事实上 | 直接陈述 | 只有在反驳前文时才保留 | 中 |
| 实际上 | 直接陈述 | 同左 | 中 |
| 众所周知 | 删掉或用引用 | 往往后面跟的不是众所周知的 | 低 |
| 大家知道 | 删掉 | 同左 | 极低 |
| 不言而喻 | 删掉 | 真正明显的事实不需要说"不言而喻" | 极低 |

## 🟡 第三类：万能修辞模板

特征：放到任何文档里都通顺，拿掉对内容没有任何影响——这就是垃圾。

| 模板 | 建议操作 | 理由 | 误报风险 |
|------|---------|------|---------|
| 在当今……的时代/背景下/浪潮下 | 删除 | 万能开头，每篇 AI 文的第一句 | 极低 |
| 随着……的发展/进步/深入 | 删除 | 同左，第二万能的开头 | 极低 |
| ……已成为不可阻挡的趋势 | 删除 | 绝对判断 + 无数字支撑 | 低 |
| 这需要各方共同努力 | 删除 | CCT典型信号——无任何可操作主体，换哪篇都成立 | 极低 |
| 我们期待更好的未来 | 删除 | 无时间/条件/行动主体的情感断言 | 极低 |
| 这将带来全新的体验 | 删除 | "全新"+无具体改进点的抽象体验 | 极低 |
| Yb 全球通吃句式(汇总行) | 符合以下特征的任何句子 | 见上方逐条；统一判定：换篇文档也成立的 = 删除 | — |
| Yb 全球通吃句式 | 删除 | 无任何地域/人群/场景特指的万金油句，换篇文档也成立——CCT(文化共识理论)揭示的"算法同质化"信号 | 极低 |
| 在这个瞬息万变的时代 | 删除 | 纯粹的情绪铺垫，对信息传递零贡献 | 极低 |
| 站在新的起点上 | 删除 | 空间隐喻 + 模糊的时间点 | 低 |
| 综上所述 | 删除或改写 | 除非前面真的有很多论点要总结 | 中 |
| 总而言之 | 删除 | 同左 | 中 |
| 归根结底 | 删除 | 同左 | 中 |
| ……是大势所趋 | 删除 | 断言漂亮但没有"怎么做" | 低 |
| 这需要各方共同努力 | 删除 | CCT典型信号——无任何可操作主体，放哪都行 | 极低 |
| 我们期待更好的未来 | 删除 | 无时间/条件/行动主体的情感断言 | 极低 |
| 这将带来全新的体验 | 删除 | "全新"+无具体改进点的抽象体验 | 极低 |
| 在这个竞争日益激烈的环境中 | 删除 | 万能结尾前铺垫 | 极低 |
| 不得不提的是 | 删除 | 和"值得注意的是"同一套路 | 极低 |
| 说到这里 | 删除 | 口语化但空洞的过渡 | 极低 |

## 🟢 第四类：结构癖 & 虚化表达

特征：不靠单个词暴露 AI 味，而是靠固定句式模式和修饰习惯。

### 4a. 排比癖

| 模式 | 说明 | 误报风险 |
|------|------|---------|
| ≥3 个"实现了 A、提升了 B、增强了 C" | 三连并列是 AI 写作的最强信号之一 | 极低 |
| 连续 ≥3 个"动词 + 了 + 名词"以顿号连接 | "选择了A、采用了B、实施了C" | 中* |
| 三段式总分总且每段开头格式一致 | "首先…其次…最后…" + 每段首句字数相近 | 低 |
| "第一/第二/第三…"连续编号列且各项为空洞原则（无具体措施/数字） | "第一，需保障数据安全；第二，不同地区可能存在合规要求差异"——每项换日常语无信息量 | 低 |

\* 两个动宾链不算问题，≥3 才触发。

### 4b. 虚化程度（虚化副词+抽象结果）

| 副词 | 后面常接的空泛结果词 | 要求 |
|------|---------------------|------|
| 大幅 | 提升、优化、改善、增强 | 必须跟上百分比或数字 |
| 显著 | 提高、降低、改进、优化 | 同上 |
| 明显 | 效果、变化、提升 | 同上 |
| 有效 | 解决、改善、提升、优化 | "有效"本身就是待验证的结论 |
| 极大 | 促进、推动、提升 | 极度空泛，AI 最爱的副词之一 |
| 全面 | 深化、推进、覆盖 | 要么列出具体覆盖了哪些，要么删 |
| 进一步 | 完善、加强、优化、提升 | "进一步"永远指向"已经做了点什么"但未说明 |
| 持续 | 优化、改进、加强 | 持续性是承诺，不是成果描述 |

### 4c. 后缀病（名词化后缀队列）

特征：英文 `-ize/-ify/-ization/-ity/-ism` 的中文直译。一句中出现 ≥2 个 → 强烈 AI 信号。**这条规则可正则扫描，不需要查词典。**

| 后缀 | 典型词 | 建议替换 |
|------|--------|---------|
| -化 | 系统化、前置化、闭环化、生态化、可视化、标准化、精细化 | 做全/提前/打通/让人看懂/按标准来 |
| -性 | 协作性、可扩展性、可维护性、稳定性、可靠性、灵活性、有效性 | 好配合/好扩/好修/稳/靠谱/灵活/说得通 |
| -型 | 管理型、服务型、驱动型、平台型 | 管事的/做服务的/推着走的/搭平台的 |
| -度 | 颗粒度、透明度、可控度、覆盖率 | 多细/明不明白/能不能控/占多少 |

> **与第一类的关系**："方法论"在🔴里已收录（属于学术黑话），但"闭环化""前置化"等派生词不进入🔴，归在此处统一扫描。
> **触发阈值**：单句中出现 ≥2 个后缀词（跨类别）→ 直接命中。单个 -性/-化 词本身不触发，需结合上下文判定——如"稳定性"出现在技术文档的正常术语中不标记；但若与"有效提升/显著改善"等虚化修饰同现，则构成 AI 味组合。

### 4d. 万能程度副词（掩盖无实质主张）

| 短语 | 作用 | 建议 |
|------|------|------|
| 一定程度上 | 把断言弱化到几乎不为空的状态 | 如果去掉也不影响意思，删 |
| 或多或少 | 同上 | 同上 |
| 某种程度上 | 同上 | 同上 |
| 相对而言 | 比较的对象不明 | 明确比较对象或删 |

### 4e. 欧化句型（英文骨架硬套中文）

特征：**语法上中文没问题，但每句翻回英文都出奇地顺**。这是欧化中文在句型层面的体现，比单个词汇更隐蔽。仅靠词表扫描会完全漏检。

| 模式 | 示例 | 问题 | 建议 |
|------|------|------|------|
| "不是X，而是Y" | 这不是简单升级，而是范式重构 | 英文 It's not X but Y 直译，表演式对比 | 直接说做了什么，不要立稻草人 |
| "是……的"判断句壳 | 这一阶段是至关重要的 / 核心在于验证环节 | It is... that... 移植，动词躲进"是"后面 | "关键就在这一步"/"核心是验证" |
| "进行/实现/完成/导致/构成"+名词 | 对代码进行验证 / 实现了对体验的提升 | conduct/achieve+noun 直译，空心动词占位 | 用真动词："验证代码"/"提升了体验" |
| "前者…后者…"代词回指 | Copilot更保守，前者关注效率 | 英文 he/hit回指习惯，中文需重复主语 | 重复名字："Copilot关注效率" |
| ≥3个修饰块+的 | 正确的、结构化的、与当前任务高度相关的信息 | 英文多重定语从句直译，中文一串"的" | 拆成短句或挑重点 |

> **扫描策略**：以上模式均可正则匹配。一条句子命中≥1个即标记🟢。

## 🟢(M) 第五类：修饰膨胀（v1.4 新增）

特征：多个不同类型的空泛修饰词堆叠在同一句中，但无具体数字支撑。这是典型的 AI "看起来什么都说了"的策略——实际上没有任何实质信息。

检测策略：**逐段落扫描**，检查是否出现 ≥2 种不同类别的修饰词，且同段不含任何数字。有数字则放行（具体数据不算膨胀）。

| 修饰类别 | 典型信号 | 示例 |
|---------|---------|------|
| 规模膨胀 | 夸大覆盖范围 | 全球范围内、全世界、全方位 |
| 广度膨胀 | 覆盖面模糊 | 广泛的、全覆盖、面面俱到 |
| 情感膨胀 | 正面评价但无证据 | 积极的、良好的、优异的、赞誉 |
| 趋势膨胀 | 向上趋势但无数据 | 持续向上、稳步提升、蒸蒸日上 |
| 历史膨胀 | 用"历史"包装空洞 | 悠久历史、博大精深、源远流长 |
| 数量膨胀 | 大量但不说清楚 | 大量、众多、无数、海量 |

> 与 4b 虚化程度的区别：4b = 单个虚化副词+抽象结果；此处 = **多类修饰词同时出现**。两者互补。

## 🔵 第七类：占位语气 / 犹豫腔调

特征：做了决定但加多条免责声明。单个占位短语正常，≥2 个叠用是强 AI 信号。

### 5a. "以……为准" / "视……而定"

| 短语 | 问题 | 建议 |
|------|------|------|
| 以实际业务情况为准 | 推责任给不可控因素 | 删掉或写具体决策 |
| 视具体情况而定 | 逃避判断 | 列出关键场景逐一判断 |

### 5b. "暂定" / "暂不" + 后续动作

| 短语 | 问题 | 建议 |
|------|------|------|
| 暂定采用方案 A | 不确定就不该出现在 PRD | 明确"Yes/No" |
| 暂不扩展 | 如果确定不做就写"不做" | — |

### 5c. "可灵活调整" / "酌情处理"

| 短语 | 问题 | 建议 |
|------|------|------|
| 可根据实际需求进行灵活调整 | 模糊承诺 | 删除，除非写明什么情况下调、调什么 |
| 酌情修改 | 谁裁量、裁量标准是什么？ | 写出裁量规则 |

### 5d. "原则上" / "大致上" + 两面下注

| 短语 | 问题 | 建议 |
|------|------|------|
| 原则上应该… | 两面下注 | 二选一 |
| 大致上可以接受 | "大致上"掩盖了不确定 | 给出具体标准 |

### 5e. 兜底占位（其他常见变体）

| 短语 | 说明 |
|------|------|
| 在合理范围内 | 无定义的约束 |
| 总体上 / 整体而言 | 掩盖不确定的判断 |
| 届时再议 / 后续视情况确定 | 把决策无限延期 |

### 5f. 合规腔嵌套（EU AI Act 治理文本风格，arXiv 2606.08172 + 政策文件衍生）

特征：用"在符合XX前提下/在合规框架内/遵循XX原则的基础上"+任何实质主张。前置条件从句本身不传递有用约束，只是把主张包在有理安全的外衣下。**单条不算问题**，≥2 个同段叠用 = 强 AI 信号——人写文档直接说主张，不确定性放独立段落。

| 短语 | 问题 | 建议 |
|------|------|------|
| 在符合用户隐私保护的前提下 | 条件本身是共识，不构成有效约束 | 删掉前提，直接给方案；如需限定写具体边界 |
| 在合规框架内我们可以… | "合规框架内"是噪音，不是具体限制 | 列出真正约束条件的具体条目号 |
| 遵循安全治理原则的基础上 | 原则列表太长 → 全变空 | 只引用与当前主张直接相关的具体条款 |
| 在保障数据安全的情况下 | 空洞前置条件，实际等于没说 | 给出具体安全措施名称 |

### 组合规则

以上任意 **≥2 个**出现在同一段 → 命中。分别标注每个命中的模式。5f 内部 ≥2 条也构成命中（同属合规腔嵌套）。

> 与第二类元话语的关系："元话语"说的是"说了自己在说但不说事"；此类说的是"做了决定但不敢确认"。互补关系。
